Intro: 
What is Type checking?
Type checking is the operation programming languages perform  to ensure that expressions, methods, functions are using acceptable data types (2 vars in + operation good vs bad). Depending on the language, adding 2 variables can result in a compilation error, not even permitting you to run it, like this floor function's double output is being assigned to an Int variable. It could also be an issue that gets detected during runtime, like here where we're trying to add, or rather concat a boolean to a string, and in some cases type coercion will do some of the work for you and ensure type correctness at runtime, dynamically fixing the operation like this Int to double. 
Type checking is performed and implemented in a number of ways, so let's talk about those uses in modern languages.

Java is a statically typed language.
What this means is that the compiler will make sure that the variables used in operations are valid during compilation, and will not compile if type mismatches are detected. In addition, Java being static means that variables cannot change, meaning be assigned a value of a different type during its runtime, and that variables need to be given an explicit data type for the compiler to use. So while you can set an integer variable a new integer value as many times as you want, you wouldn't be able to assign it a double.

Arrays are a bit more complicated, but work largely the same way. So if you declare the array, and then initialize it as an array with 4 elements, you can later initialize it as an array of 5 elements. The important part is that the type of value contained in each item of the arrays are the same, meaning in this case they are both integer arrays first and foremost.

Functions also need to specify what data types each argument is, as well as the output data type of that function.

With all that being said, Java is not that simple.

First, there's type coercion. Type coercion is basically a shortcut for a language saying that operations may not be using quite the intended data types, but the types chosen in that instance are deemed acceptable, and the language automatically casts the data type so that the operation can continue, because the intent of the statement is clear. In this example, even though the floor function typically expects a double and not an integer like we've provided, because integers can be safely cast to a double with no confusion or data lost, by simply stating it has 0 decimals, Java is willing to cast it and allow the compilation. The line right after does something similar, casting the double 'a' to a string to conatenate the string for the printing, which outputs 4.0 since remember, it was a double before this. Widening, such as arithmetics operations between an int and a long or a float is another common coercion.

Some other languages have another way of denoting equivalence, called structural equivalence. In a language such as Golang, several data types can be considered equivalent if their structure are the same. For example, if you have 2 structs with the same attributes, and in the same order, you can perform select methods on both of them, even though you may not consider them to be the same. Among others, this includes comparisons (though not if they are both named, so using an unamed struct here works). Assignments aren't exactly permitted since they are still considered different types with a different name, but they do allow for castings that don't require manual implementations. Arrays in golang, not being a named type either, are equivalent if their value type and length are the same. Their values being different would return false from a comparison, but a different length or type altogether would cause a compile error, because they are not structurally equivalent. Popular languages offer structural typing in some contexts, but it is fairly uncommon for it to be the main design.

But even Golang is a statically typed-language, but not all languages are: Python remains as a dynamically typed language. What that means is that unlike statically typed languages, variables don't need to have an explicitely set type, can be given values of different types throughout its execution, and not just in more fringe cases like in the inheritance example earlier. Being an interpretive language means Python doesn't compile its code beforehand, so that must mean that Python will only ever perform type checking on the code as it gets executed. Incidentally, this means that if a function or some other code would raise a TypeError but is never called, then no error will be thrown.

But Python does have annotations for type hints. These can be used for variables, and functions's parameters and outputs. They function similarly to the type declarations as seen earlier in Java, but matching the dynamic typing, are generally looser as well. For example, a list of integers can be hinted to be exactly, that, or more broadly as just a list, though usage of the mypy library will require more string hints. In addition, unions are also available, meaning an input is considered acceptable if it corresponds to any of the types in that union. Wrapping the type in with Optional means that None, Python's null equivalent, is also a permitted value. Python's tuples can effectively be used to return multiples outputs, and these can be reflected in the hints as well.
